# Stage 4: what each parallel track may touch

The seam slice (S4.00) registers every shared piece once. After it a track only **adds files** in its own places and **fills in** the placeholders the seam created for it. This page lists, per track, what it owns and what it must leave alone. If a track needs a change outside its list, that is a new seam commit (ask for it), not an edit made in passing. It follows the layout of `docs/stage3-tracks.md`.

The tracks are A billing and payments (S4.01 to S4.05), B reports (S4.06, S4.07, S4.14), C AFIP invoicing (S4.08 to S4.13) and D integration (S4.15 to S4.17). Run order and dependencies are in `tasks.md`: A (S4.01), B (S4.06) and C (S4.08, S4.09) start together; S4.10 waits for S4.02 (charge lines), S4.14 waits for S4.03 and S4.10, S4.13 waits for S4.04 and S4.11; D starts when A, B and C are merged.

There is no payments gateway port in Stage 4: payments are recorded by hand (cash, cards through a terminal, transfers). The gateway (`PaymentsGateway`, Mercado Pago) belongs to Stage 6 (S6.03). The one new port is `invoiceIssuer`.

### Navigation ids

`app/nav/nav-config.ts` no longer defines `cash` or `reports`; the features contribute them, so no track edits the shell. The subscription of Stage 6 keeps the shell id `billing` and the path `/billing`, so the charges screen is **`/charges`**, not `/billing`. The invoicing settings (fiscal profile, points of sale, credential) are a settings tab (`settingsTabs`, route mounted under `settings`, permission `invoicing.configure`) in the same `nav.ts`.

### Permissions the seam added

`pricing.manage`, `charges.void`, `payments.refund`, `invoicing.configure`, `invoicing.credit_note` and `invoicing.manual` belong to owner and admin; `invoicing.issue` to owner, admin and reception. None is grantable or clinical. The seam also gave `reports.read` to **professional and reception** (it was owner and admin only): the reports spec scopes them on the server (a professional reads their own figures, reception its locations and never revenue by professional), and a route cannot be reached without the permission. Track B's `application/scope.ts` is the one place that decides what each role sees.

## Rules for everyone

1. Run `pnpm db:restamp` and `pnpm db:check` after every merge or rebase that touches the journal.
2. Add a locale file for every screen text; no literal text in JSX (lint).
3. A web feature imports another feature only through its `index.ts` (lint).
4. Cross-module calls on the API go through `modules/<other>/index.ts` and through the appointment events.
5. Every mutating route declares `config.audits`, every route a read-only category, every job its queue category.
6. Money is `Money` end to end: integer cents in the database (`bigint` or `integer` columns named `*_cents`), in the API and in the browser. Percentages go through `applyBasisPoints`, splits through `allocateProportional`. Text for people comes from `formatMoney`; text typed by people goes through `parseMoney` or `MoneyInput`.
7. A download is never a new route: register a `FileResource` and let `/files/:token` serve it.
8. Anything a simulator produces says so: `SimulatedBillingNotice` on the screens, the `watermark` option of `renderPdf` on documents.
